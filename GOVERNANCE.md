# Governance

StreamProbe uses a lightweight maintainer model while the community is small.

## Roles

- **Contributors** participate through issues, pull requests, documentation, design, testing, and community support.
- **Reviewers** are recurring contributors trusted to triage issues and review within areas they understand.
- **Maintainers** merge changes, cut releases, manage security reports, and steward project direction.

Roles are earned through sustained, constructive participation. Maintainers should invite qualified contributors rather than requiring self-nomination. Access can be reduced after extended inactivity or conduct/security violations, with private communication where possible.

## Decisions

Routine changes use lazy consensus in issues and pull requests. Public API, dependency, scoring, governance, and security-boundary changes require a documented proposal and maintainer approval. When consensus is not possible, maintainers record the decision and rationale publicly unless security or privacy prevents it.

## Independence

Project decisions prioritize users and the open-source community. Tool vendors and commercial users receive no automatic governance rights. Assistance from Claude Code is disclosed, but Anthropic does not govern, sponsor, or endorse the project unless a future public agreement explicitly says otherwise.
